# 窗口布局、置顶和焦点策略

## 交互桌面边界

服务运行在当前 Windows 登录用户的交互桌面会话中，必须能枚举 QQ 窗口、调用 Win32 API 和模拟鼠标键盘。它不是 Windows Service，也不应运行在无交互桌面的会话中。

## 窗口就绪分级

`ensure_qq_window()` 使用 L1/L2/L3 分级：

- L1：每次确认 QQ 主窗口存在。
- L2：窗口句柄、位置、尺寸和非最大化状态与快照一致时，直接复用。
- L3：窗口最小化、移动、缩放或快照失效时，置顶、整理形态并做 WGC 试截。

窗口形态统一为：

```text
工作区高度铺满 + 工作区宽度 50% + 靠左
```

这样列表、输入框和发送按钮都在可点击范围内。

## 临时置顶

`WindowCaptureCtx` 用于点击或截图前临时置顶：

- 使用 `SWP_NOACTIVATE`，置顶但不主动抢键盘焦点。
- 不移动窗口、不改变窗口尺寸。
- 记录窗口原来是否已经是 TOPMOST。
- 原本不是 TOPMOST 的窗口，退出上下文时恢复普通层级。
- 原本就是 TOPMOST 的窗口，不重复设置，也不在退出时错误取消。

## 为什么不永久置顶

永久置顶会改变用户桌面层级，干扰用户正在使用的其他窗口。临时置顶只覆盖实际交互窗口，退出后恢复原状态。

## 已知风险

- 置顶仍可能触发某些 QQ 版本的异步重绘或列表滚动。
- 多显示器混合 DPI 下，窗口所在显示器的实际缩放需要单独验证。
- 若其他 TOPMOST 窗口覆盖 QQ，临时置顶不一定能保证可见；点击闭环仍应通过右上角 OCR 验证。
