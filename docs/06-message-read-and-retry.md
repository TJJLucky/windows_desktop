# 消息读取与失败语义

## 读取流程

`MessageList.read_messages(qq_number)` 是消息读取的唯一入口：

1. 通过 `UserList.active_user_by_number()` 激活目标会话；联系人定位只按右键菜单复制的 QQ 号，不使用昵称 OCR。
2. 通过消息区模板确定框选范围：矩形四边相对消息区内缩 8px，起点再向下让开消息
   区顶部约 20px 的粘性日期栏命中区，并逐行寻找气泡左侧边距上的空白画布作为按下点。
3. 从该起点按住左键拖到矩形右下角，进入 QQ 多选状态；界面没有出现框选态时把起点
   整体下移一个守卫高度重试，最多 3 次。
4. 优先匹配 `templates/copy_icon.png`；工具栏图标模板不匹配时，回退到底部 ROI 的
   OCR 精确文字“复制”，再按文字标签定位其上方的图标点击区域。
5. 读取 QQ 写入系统剪贴板的 Unicode 文本。
6. 按 `发送人: MM-DD HH:MM:SS 正文` 解析为 `sender`、`timestamp`、`text`、`rawText`；
   私聊/服务号仅复制正文时，`sender` 保持为空，由调用智能体按自身判断归属，`timestamp` 保持为空。

消息正文不再使用气泡检测、拼图或 OCR，也不返回气泡坐标或方向。智能体应根据
`sender` 与自身 QQ 名称自行判断消息归属。

## 框选几何

真机实测（会话 `110001335` / `2885099490` / `2885512390`，各重复 2 次）：

- 消息区左边界落在 QQ 的 `SIZEWE` 命中区上，按下点需让开 3px 才能进入框选态；右、
  下边界让开 0~8px 都能成功。四边统一内缩 8px，起点横向仍用 `find_non_resize_x`
  按真实光标命中区动态探测。
- 消息区顶部是粘性日期栏的命中区：已滚动的会话约 20~21px 高，按下点落在其中不会
  进入框选态；未滚动、顶部没有日期栏的会话几乎立刻可以按下。代码固定让开 22px。
- 起点必须落在空白画布上：气泡、头像与区域边界上的按下都只被当成普通点击。因此在
  气泡左侧 56px 边距内逐行扫描 `#f5f5f5`，再按尺寸调整命中区修正横坐标。
- 只要拖拽矩形与消息相交，QQ 就会选中整条消息，起点落在第一条消息内部不会漏掉它；
  矩形必须覆盖至少一条消息，落在纯空白画布上不会进入框选态。

## 失败语义

框选、复制图标定位、剪贴板读取或复制文本格式解析失败时，`MessageList` 抛出明确的
`RuntimeError` 错误码。上层将其投影为 `QQ_MESSAGES_UNAVAILABLE` 与 HTTP 503。

复制操作会改变系统剪贴板；服务只在确认复制动作存在后写入唯一哨兵，并只接受本次
复制后出现的非空 Unicode 文本。复制动作定位失败时不会提前覆盖用户原剪贴板。
